JavaScript 的執行順序可以分為兩個階段：全域（Global）執行階段和函式執行階段，這與 JavaScript 的執行環境（Execution Context）有關。

JavaScript 執行環境的順序
全域執行階段（Global Execution Context）

當 JavaScript 檔案被載入時，會先創建全域執行環境，負責執行所有在全域範圍內的程式碼。
全域的變數和函式會在這個階段被初始化。
如果程式中有函式的定義，函式本身不會立即執行，只是被登記在內存中，等到後續被呼叫時才執行。
函式執行階段（Function Execution Context）

當某個函式被呼叫時，會為該函式創建一個新的執行環境。
在函式執行階段中，會處理函式的參數、內部變數以及執行具體的程式碼。
執行順序具體說明
全域程式碼先執行：

程式會依次執行全域作用域的程式碼，遇到函式定義時，會將函式存放在記憶體中，但不執行函式內容。

遇到函式呼叫時：

創建一個新的函式執行環境，暫停全域程式碼的執行，先處理函式內容。
當函式執行完成後，會回到全域執行環境，繼續執行剩下的程式碼。

Event Queue 和 Event loop

Event Queue(事件儲列)
在寫網頁程式時 有一些所謂[內建的]API像 setTimeout setInterval
這些API不存在js的原始碼內,但仍然可在開發時直接使用
因為這些API是屬於瀏覽器所提供的 Web API 非js引擎的一部分
或者是:
操作DOM節點的API:document.getElementById
AJAX相關的API像是:XMLHttpReuest(https://summer10920.github.io/2020/12-14/article-ajax-api/)
計時類型的API像是:setTimeout

這類Web API 在與JS原始碼一起執行時,不會直接影響JS主執行環境的運行

事件儲列 專門用來存放這些非同步的函式 等到整個主執行環境運行結束後
才開始依序執行事件儲列裡面的函式 而Queue是一種先進先出的資料結構

setInterval給定的時間,固定幾秒執行一次
setTimeout給定的秒數之後執行一次
setInterval(function,3000(秒速))

ex:6-9
1.js引擎執行到瀏覽器提供的seTimeout函式
2.js引擎繼續運行,同時瀏覽器開始根據給定秒數計時
3.計時完成後,把剛接收到的函式推送到 Event Queue
4.等待js引擎運行完畢,主執行環境結束後(所有函式執行環境和全域執行環境)
,將Event Queue內的函式推送到js主執行環境並執行

Event Loop(事件迴圈)6-12
可想像成無時無刻都在執行的程式,負責檢查現在主執行環境
堆疊是否為空,若是空的,再去檢查Event Queue,若Event Queue
