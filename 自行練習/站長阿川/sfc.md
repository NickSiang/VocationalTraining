為什麼要使用 SFC？
單檔組件（Single File Components, SFC）是 Vue.js 框架提供的一種功能，允許開發者將 HTML、CSS 和 JavaScript 整合在一個 .vue 文件中。雖然使用 SFC 必須搭配構建工具（如 Vite 或 Vue CLI），但它帶來了以下顯著的優勢：

模塊化組件：可以使用熟悉的 HTML、CSS 和 JavaScript 語法編寫模塊化的組件，方便管理和重用。
關注點內聚：將模板（HTML）、邏輯（JavaScript）和樣式（CSS）這些本來就高度相關的部分自然整合在一起，提升代碼的可讀性。
預編譯模板：模板在構建時被預編譯為 JavaScript，避免運行時的編譯開銷，從而提升應用性能。
組件作用域的 CSS：SFC 中的 <style> 可以設定作用域（例如使用 scoped 屬性），確保樣式僅影響當前組件，避免全局樣式污染。
語法更簡單：特別是在使用 Vue 3 的組合式 API（Composition API）時，SFC 的語法更加簡潔直觀。
編譯時優化：構建工具可以通過交叉分析模板和邏輯代碼，在編譯時進行更多性能優化。
更好的 IDE 支持：SFC 提供自動補全功能，並支持對模板中表達式的類型檢查，提升開發效率。
模塊熱更新（HMR）支持：開發過程中，SFC 開箱即用支持熱更新，修改代碼後無需刷新頁面即可看到效果。
由於這些優勢，SFC 被 Vue 官方推薦為以下場景的項目組織方式：

單頁面應用（SPA）：適合需要高效組件管理的複雜應用。
靜態站點生成（SSG）：如使用 Vue 搭配 Nuxt.js 生成靜態網站。
任何值得引入構建步驟的項目：只要追求更好的開發體驗（DX），SFC 都是理想選擇。
然而，在一些輕量級場景中，SFC 可能顯得過於「重量級」。針對這種情況，Vue 提供了 petite-vue，這是一個僅約 6 kB 的預優化 Vue 子集，無需構建工具，適合用於漸進式增強的簡單交互需求。

SFC 是如何運作的？
Vue SFC 是一種特定的檔案格式（.vue），需要通過 @vue/compiler-sfc 編譯為標準的 JavaScript 和 CSS。其運作機制如下：

編譯過程：

SFC 文件中的 <template>、<script> 和 <style> 會被編譯器解析。
編譯後，SFC 成為一個標準的 JavaScript（ES）模塊，可以像其他模塊一樣被導入。

CSS 處理：

開發環境：SFC 中的 <style> 標籤會被注入為原生的 <style> 標籤，支持熱更新（HMR）。
生產環境：樣式會被抽取並合併成單獨的 CSS 文件，優化資源加載。
構建工具支持：

在實際項目中，SFC 通常搭配整合了編譯器的構建工具使用，例如：
Vite：基於 ES Modules 的快速構建工具。
Vue CLI：基於 webpack 的傳統構建方案。
Vue 官方還提供腳手架工具，幫助開發者快速上手 SFC 開發。
你可以在 Vue SFC 演練場 中實時體驗單檔組件，並查看它們編譯後的結果。更多工具鏈相關信息，可參考官方的 SFC 工具鏈章節。

如何看待關注點分離？
對於 SFC 將 HTML、CSS 和 JavaScript 整合在一個文件中的做法，部分傳統 Web 開發者可能會質疑這是否違反了「關注點分離」（Separation of Concerns）的原則。以下是對此的解釋：

傳統觀點的誤解：
傳統上，關注點分離被理解為將 HTML（結構）、CSS（樣式）和 JavaScript（行為）分離到不同的文件中。
但這種分離方式在現代前端開發中並不總是最佳選擇，尤其是在組件化開發的背景下。
現代 UI 開發的視角：
在當今前端工程化中，關注點分離的目標是提高代碼的可維護性和可擴展性，而非機械地按文件類型分割。
與其將代碼按類型分為三個相互交織的大層，不如將應用拆分為鬆散耦合的組件。
在一個組件內，模板、邏輯和樣式本質上是高度耦合的，將它們放在一起反而能提升內聚性，使組件更易於理解和維護。
靈活的選擇：
如果你不喜歡 SFC 的形式，Vue 仍然支持將 JavaScript 和 CSS 分離到獨立文件中。
通過資源導入功能（例如 import），你依然可以享受熱更新和預編譯等優勢。
總結
SFC 是 Vue.js 提供的一種強大功能，通過將 HTML、CSS 和 JavaScript 整合在一個 .vue 文件中，實現了模塊化開發、性能優化和更好的開發體驗。雖然它依賴構建工具，但其優勢使其成為單頁面應用（SPA）、靜態站點生成（SSG）等場景的首選方式。對於輕量級需求，Vue 也提供了無構建工具的替代方案如 petite-vue。此外，SFC 的設計並未違背關注點分離的原則，反而適應了現代前端開發的需求，兼顧了靈活性和實用性。
